过去两年我用过的 AI Agent 工具，可以分成三类。

一类活在终端里。它们对开发者很好用，但每次想跑一个任务都要先想清楚命令、参数和工作目录，对非工程师是冷启动劝退。

一类以聊天优先。门槛低、容易上手，但它们几乎不碰你的本地工作区——你问它一个项目的事，它只能基于聊天历史猜；你想让它"看一眼这个文件夹"，它做不到。

还有一类是云端 Agent。它们能跑长任务，但执行细节常常被藏起来，你的文件、上下文、提示词都在别人的服务器上转了一圈。

Duya 走的是第四条路。它把 AI 智能体装进一个本地优先的桌面应用，让它真的能用你的浏览器、读你的文件、跑你的终端、操作你的项目，同时每一步都在你眼前。

## Duya 到底是什么

Duya 是一个本地优先的桌面 AI 智能体客户端，覆盖研究、文件、代码与可视化工作流。它不是一个聊天框加几把工具的拼凑，而是一个统一的工作区，浏览器、文件、终端、画布、插件、技能、权限都装在同一个桌面应用里。

当 Duya 在做事时，它把每一步渲染成可见的工具卡片——读哪个文件、跑哪条命令、点哪个网页、写哪段代码——敏感操作会先停下来请求你的批准。这件事听上去像基本要求，但大部分 Agent 工具不做。

## 它和聊天助手有什么不一样

聊天助手擅长的是回答问题、写作、解释概念。它们的边界也很清楚：没有真实的本地执行能力，问它们"我硬盘里那个文件第一行写的什么"，它们只能猜。

Duya 的设计目标是给智能体真正的桌面工具：

- 真实的浏览器操作：打开页面、点击、输入、滚动、截屏、读取网络输出，而不是只调搜索 API。
- 本地文件的读写、搜索与编辑：read、grep、glob、edit、write 这些编码 Agent 工具在 Duya 里都能用，并且从工具卡片里就能打开生成或修改过的文件。
- 集成的终端面板：智能体可以跑 shell 命令、看输出、把终端结果作为任务循环的一部分；敏感命令走权限门控。
- 项目引用面板：你可以挑出对当前任务最重要的几个文件作为引用，智能体把它们当作工作上下文的一部分，而不是从一堆散落的文件里猜。

## 它和 IDE 里的编码 Agent 有什么不一样

IDE 编码 Agent（Cursor、Claude Code 插件、Copilot Workspace 这类）确实很强，它们专门为代码库任务优化。但它们的形状是"编辑器里的侧边栏"，离开 IDE 就没用。

Duya 的形状是"桌面应用"：

- 它不绑死某一个编辑器。你用什么编辑器都行，Duya 关心的是项目和文件，不是哪一行高亮。
- 它的工作流覆盖研究 + 文件 + 代码 + 可视化四块，不只是写代码。做一个"用浏览器研究三个竞品 → 在本地写一份对比 markdown → 顺便画个对比图"的任务，Duya 是一站式的。
- 它有 Agent Mailbox：智能体正在跑长任务时，你可以往里塞后续指令，它会接到并继续，不需要等它跑完才能改方向。

## 它和云端 Agent 有什么不一样

云端 Agent 的优势是能跑很长的任务、能用很大的上下文。代价是你的数据出去了——对话、工作区、文件、提示词，至少要在它们的服务器上走一遍。

Duya 的设计前提是"用户的电脑就是主要工作区"：

- 工作区数据默认本地存。Duya 不需要 Duya 云工作区来承载你的本地会话。
- 你自己选模型服务商、自己管 API key。模型请求只发给你配置的那家。
- API key 本地存储，使用操作系统级保护，在 UI 里脱敏显示。
- 工具操作可见，敏感操作走权限门。

## 它和浏览器自动化工具又有什么不一样

浏览器自动化工具（Playwright、Selenium、Browser Use 之类）解决的是"网页操作"这一件事。它们不读你的项目文件、不写你的本地笔记、不给你画布、不管权限。

Duya 把浏览器当作众多工具中的一个，并且它和文件、项目、终端是打通的。一个典型的 Duya 任务是：用浏览器研究三款 AI 编码工具，落到本地 markdown 笔记里，附上截图，再生成一个对比小卡片——这件事在纯浏览器工具里要做四遍。

## 几个值得单独提的能力

### 可视化产物与自检

Duya 可以在聊天里渲染 widget、图表、仪表盘、流程图。更重要的是，它有一个可视化自检流程——智能体可以检视自己刚渲染出来的图，发现问题再改进，而不是只生成原始 markup 就交差。

### Conductor 画布

Duya 包含一个实验性的 Conductor 模式，用于基于画布的智能体工作。它支持画布元素、智能布局、视感知的打包、对齐吸附、碰撞处理、自动布局工具，以及智能体驱动的画布操作。这是 Duya 更长期的方向：不只是和智能体聊天，而是在一个桌面空间里协调任务、产物、上下文与可视化工作流。

### 多服务商架构

Duya 不绑死某一家模型。你可以同时配 OpenAI、Anthropic、Gemini、本地 Ollama 等等，按工作流切换服务商、切换模型，API key 全部本地管理。

### 插件 / 技能 / MCP 风格的扩展层

Duya 的扩展不是封闭生态。它有插件、技能，以及一个面向 MCP 风格工具的接入层，这意味着社区里成熟的 MCP 工具能比较自然地接进来。

### 隔离的智能体运行时

底层结构上，Duya 的智能体跑在隔离的 worker 进程里，本地持久化用 SQLite。这件事普通用户看不到，但它决定了智能体的运行可以被中断、恢复、审计，比单一进程内的聊天循环更可靠。

## 它当前适合谁

- 一个人同时做研究、写代码、整理文件、画图的工作流型用户。
- 对数据留在本地这件事有要求的用户。
- 已经在用多个 AI 工具（聊天 + 编码 IDE + 浏览器自动化 + 画图）并希望合并到一个工作区的用户。
- 想自己选模型服务商、不想被某一家绑定的用户。

## 它当前不适合谁

Duya 还处于 beta。下面这些事情是真实的限制，写出来而不是藏着：

- 第一次安装和首次配置模型服务商的体验还在打磨。
- macOS 与 Linux 包相对 Windows 测试得更少，可能需要更多冒烟测试。
- Conductor / 画布功能是实验性的，期望它是"还能用但偶尔会撞墙"。
- 企业工作区不是当前公开测试的重点。

## 一句话总结

如果你希望 AI 智能体能在你的桌面上做真实的事，并且每一步你都能看见、都还能拦下来，Duya 是当下少数几个把这件事当作核心而不是附加功能的工具。

它不是聊天框加搜索的拼凑，也不是藏在 IDE 侧栏的补全，也不是把你的工作区搬到云端的长任务跑腿。它是"用户的电脑就是主要工作区"这件事认真做了一遍的桌面应用。
